# Титан в Dota 2 против Codex и Claude

Публичный YouTube-эксперимент: **человек с рангом «Титан»** соревнуется с **Codex** (OpenAI API)
и **Claude** (Anthropic API) на рынках The International в Polymarket.
Каждому участнику выдаётся отдельный виртуальный капитал **$1000 USDC**.

> ## ⚠️ Только paper trading
> Проект **не совершает реальных сделок**. В кодовой базе нет ни подписи транзакций,
> ни приватных ключей, ни клиента для отправки ордеров. Константа
> `app/config.py::LIVE_TRADING_ENABLED = False` захардкожена, `PaperExecutionEngine` —
> единственная реализация исполнения, а тест `tests/test_no_live_trading.py`
> сканирует репозиторий на следы реального исполнения и падает, если они появятся.

## Быстрый старт

Без единого API-ключа. Требуется Python 3.12.

```bash
git clone <repo> && cd PM-INTERNATIONAL

python3.12 -m venv .venv
source .venv/bin/activate
pip install -r requirements-dev.txt

cp .env.example .env          # значения по умолчанию уже рабочие

python -m app.cli demo        # полный демо-раунд: snapshot → решения → расчёт
uvicorn app.main:app --reload # панель на http://localhost:8000
```

Через Makefile — то же самое:

```bash
make install
make demo
make run
```

### Windows

`make` и Makefile здесь не работают: он написан под POSIX (`.venv/bin`, `rm`,
`find`). Вместо него — `run.ps1` с теми же командами:

```powershell
git clone <repo>; cd PM-INTERNATIONAL

.\run.ps1 install             # venv + зависимости, сам найдёт Python 3.12
Copy-Item .env.example .env

.\run.ps1 demo                # полный демо-раунд без ключей
.\run.ps1 run                 # панель на http://localhost:8000
```

`.\run.ps1` без аргументов покажет все команды (`test`, `seed`, `export`,
`status`, `doctor`, `clean`, `migrate`).

Если PowerShell откажется запускать скрипт, разрешите локальные скрипты:

```powershell
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
```

Docker на Windows не обязателен — проект работает на SQLite без него.

Что вы увидите после `make demo`:

```
1. Рынок: Team Spirit vs Falcons — победитель серии (TI Playoffs)
2. Snapshot #1 зафиксирован, раунд #1 открыт
3. Codex и Claude ответили (mock-режим), решения скрыты
4. Titan подал решение, раунд заперт: LOCKED
5. Risk engine + paper execution:
   codex   APPROVED  41.19 → 41.19 USDC, исполнено 102.06 @ 0.4036
   claude  APPROVED  87.59 → 87.59 USDC, исполнено 142.10 @ 0.6164
   titan   APPROVED  75.00 → 75.00 USDC, исполнено 121.67 @ 0.6164
6. Решения раскрыты
7. Рынок рассчитан: победил YES
```

## Как проходит раунд

1. **Оператор выбирает рынок** на `/ui/markets` и при желании добавляет контекст
   (составы, замены, новости турнира) — он попадёт в snapshot и будет одинаков для всех.
2. **Система фиксирует snapshot**: ID и название рынка, команды, тип рынка, время начала,
   цены YES/NO, ликвидность, bid/ask, доступная глубина, последние изменения цены,
   время получения данных, заметки оператора. Payload неизменяем, его SHA-256 хранится в БД.
3. **Codex и Claude запрашиваются одновременно** (`ThreadPoolExecutor`) по одному и тому же
   snapshot и с одинаковым промптом.
4. **Titan вводит решение вручную** на `/ui/rounds/{id}/titan`. После отправки решение
   блокируется от редактирования.
5. Когда все трое подали ответ, раунд переходит в статус **LOCKED**.
6. **Risk engine** проверяет каждое из трёх решений и пишет журнал причин.
7. **Paper engine** симулирует исполнение одобренных заявок.
8. Только теперь раунд можно **раскрыть** — появляется сравнительная таблица.

Статусы: `OPEN → LOCKED → EXECUTED → REVEALED`, плюс `CANCELLED`.
Повторное исполнение блокируется на двух уровнях: проверка статуса раунда и
UNIQUE-ограничение `simulated_orders.decision_id`.

### Фазы: PREMATCH и BETWEEN_MAPS

Поддерживаются только две фазы. **Ставок внутри карты в реальном времени нет** — это
осознанное ограничение.

Для `BETWEEN_MAPS` оператор вручную подтверждает окончание карты
(`POST /api/rounds/between-maps?market_id=…` с `map_number`), система делает **новый snapshot**,
а предыдущий помечается `superseded_by_id`. Любое решение по старому snapshot будет
отклонено risk engine с причиной `stale_snapshot`.

## Правила эксперимента

| Правило | Как обеспечено |
|---------|----------------|
| Три независимых банка по $1000 | Отдельные `Portfolio`; списание у одного не влияет на других (`test_isolation.py`) |
| Все видят один snapshot | Один `Snapshot` на раунд, payload с SHA-256, участники получают его копию |
| Никто не видит чужих решений до фиксации | `GET /api/rounds/{id}/decisions` возвращает `hidden: true` до статуса EXECUTED; страница Титана и страница раунда не рендерят чужие ответы |
| Приватность не обходится через побочные каналы | статистика и отчёт о расхождениях считаются только по раскрытым раундам; экспорт не включает нераскрытые раунды; в аудит пишется SHA-256-отпечаток решения, а не его содержимое |
| Codex не получает данных больше, чем Claude | Промпты собирает общий `prompting.build_prompt`; тест сравнивает их посимвольно |
| Решение нельзя переписать | `locked=True`, UNIQUE `(round_id, participant_id)`, правки только через новую запись аудита |
| Невалидный ответ не исполняется | Схема Pydantic + статус `INVALID`/`FAILED` → risk engine отклоняет |

## Risk engine

Лимиты одинаковы для всех участников, настраиваются в `.env`, значения по умолчанию безопасны:

| Параметр | Env | По умолчанию |
|----------|-----|--------------|
| Максимум на одну позицию | `RISK_MAX_POSITION_PCT` | 10% банка |
| Максимум на один матч | `RISK_MAX_MATCH_PCT` | 25% банка |
| Максимум в открытых позициях | `RISK_MAX_TOTAL_EXPOSURE_PCT` | 50% банка |
| Минимальная ставка | `RISK_MIN_STAKE_USDC` | 1.0 |
| Минимальная ликвидность | `RISK_MIN_LIQUIDITY_USDC` | 50.0 |
| Максимальное проскальзывание | `RISK_MAX_SLIPPAGE_BPS` | 300 б.п. (3%) |
| TTL snapshot | `RISK_SNAPSHOT_TTL_SECONDS` | 900 с |

Дополнительно движок запрещает: отрицательный баланс, исполнение по устаревшему snapshot,
повторное исполнение одного решения, покупку выше `max_acceptable_price`.
`HOLD` всегда допустим. Вердикты: `APPROVED`, `ADJUSTED` (заявка урезана), `REJECTED`.
Каждый вердикт сопровождается списком причин с кодом, текстом и уровнем — они сохраняются
в `risk_evaluations.reasons` и видны на экране раскрытия.

## Paper execution engine

- Покупка идёт по `asks`, продажа — по `bids` из snapshot, уровень за уровнем.
- Частичное исполнение, если глубины не хватает или сработал `max_acceptable_price`.
- Проскальзывание = отклонение средней цены исполнения от лучшей котировки, в б.п.
- Комиссия `PAPER_FEE_BPS` от оборота (по умолчанию 0).
- Средства резервируются на время исполнения, неиспользованный резерв возвращается.
- Позиции ведутся по исходам YES/NO со средней ценой и `cost_basis`.
- `SELL` закрывает позицию (полностью или частично) и фиксирует realized PnL.
- Settlement после ручного ввода результата: победивший исход гасится по 1.00, проигравший по 0.00.
- **Воспроизводимость**: результат зависит только от snapshot и заявки; seed исполнения
  детерминированно выводится из `(round_id, participant_id, market_id, payload_hash)`.
  Случайных чисел в исполнении нет вообще.

## Статистика и победители

Считается отдельно по каждому участнику (`GET /api/stats/scoreboard`):

конечный банк · абсолютный и процентный PnL · ROI · realized/unrealized PnL · win rate ·
число ставок · средняя ставка · максимальная просадка (абсолютная и в %) ·
**Brier score** · **log loss** · калибровочные корзины · PnL по фазам PREMATCH/BETWEEN_MAPS ·
PnL по командам · PnL по типам рынков.

Победителей двое:

- 🏆 **Лучший трейдер** — по итоговому банку (equity);
- 🎯 **Лучший прогнозист** — по качеству вероятностных прогнозов (Brier score, меньше — лучше).

Это разные зачёты: можно угадывать вероятности лучше всех и при этом проиграть по банку.

## Экспорт для YouTube и Telegram

`GET /api/export/...` и кнопка на `/ui/exports`. **Ничего не публикуется автоматически** —
создаются только файлы, оператор выкладывает их сам.

| Формат | Что внутри |
|--------|-----------|
| `csv` | таблица «раунд × участник»: действие, вероятности, edge, ставка, исполнение, обоснование |
| `daily-scoreboard` (CSV) | банки участников по дням |
| `json` | полный дамп: scoreboard, статистика, расхождения, крупнейшие движения |
| `report` (HTML) | готовый к съёмке отчёт: scoreboard, победители, график, топ выигрышей и проигрышей, расхождения, объяснения решений |
| `chart.svg` | график динамики банков (самодостаточный SVG, без внешних библиотек) |

`POST /api/export/write` или `python -m app.cli export` сохраняет весь комплект в `EXPORT_DIR`.

## Подключение реальных источников и моделей

### Polymarket (публичные данные, ключи не нужны)

```bash
MARKET_DATA_PROVIDER=polymarket
POLYMARKET_GAMMA_URL=https://gamma-api.polymarket.com
POLYMARKET_CLOB_URL=https://clob.polymarket.com
POLYMARKET_SEARCH_QUERY=The International   # пусто или Dota — все матчи Dota 2
POLYMARKET_GAMMA_TAG_ID=102366              # тег Dota 2 в Gamma
POLYMARKET_MAIN_MARKET_ONLY=true            # только победитель серии
POLYMARKET_ONLY_UPCOMING=true               # скрывать начавшиеся матчи
```

Адаптер `app/adapters/market_data/polymarket.py` читает `GET /events?tag_id=…`
(Gamma) и `GET /book?token_id=…` (CLOB), нормализует события, сохраняет сырые
ответы в `raw_market_payloads`. Если рынок исчез, закрылся или сменил структуру —
поднимается `MarketNotAvailable`, раунд не создаётся, событие пишется в аудит.

Поиск идёт **по тегу**, а не перебором активных рынков: на Polymarket
одновременно живут тысячи рынков, и выборка «первые N активных» не содержит
Dota 2 вовсе. Если Polymarket когда-нибудь сменит тег, поиск перестанет
находить матчи — новый номер указывается в `POLYMARKET_GAMMA_TAG_ID`, код
менять не нужно.

У одного матча Polymarket публикует 20-30 рынков: победитель серии, победитель
каждой карты, форы, тоталы, экзотика. По умолчанию берётся только основной
рынок серии; `POLYMARKET_MAIN_MARKET_ONLY=false` открывает остальные, и они
попадают в статистику по типам рынков как `MAP_WINNER`, `HANDICAP`, `TOTALS`,
`SPECIAL`.

**Приватные ключи Polymarket не поддерживаются намеренно.** Для чтения рынков они не нужны,
а подпись ордеров вне области этого проекта. Если позже понадобится live-режим —
это отдельная задача с отдельным явным разрешением: нужно будет реализовать
`ExecutionEngine` рядом с `PaperExecutionEngine` и снять хардкод `LIVE_TRADING_ENABLED`.

> О папке `arb_scan_stake`: из неё переиспользован номер тега Dota 2 в Gamma
> (`102366`, см. `polymarket_dota2.py`) — именно его не хватало, чтобы поиск
> находил матчи. Сам клиент не переносился: там он завязан на сопоставление со
> Stake и на общий движок esports-профилей.
>
> Если захотите подключить свой клиент целиком, оберните его в класс,
> реализующий интерфейс `MarketDataProvider` (три метода: `search_markets`,
> `get_market`, `get_quote`), и зарегистрируйте в
> `app/adapters/market_data/factory.py` — остальной код менять не нужно.
> Переносите **только чтение данных**: `arb_scan_stake` умеет отправлять ордера
> и хранит `POLY_PRIVATE_KEY`, и ни то, ни другое в этом проекте недопустимо.
> Тест `tests/test_no_live_trading.py` упадёт, если такой код появится.

### Claude (Anthropic)

```bash
ANTHROPIC_API_KEY=sk-ant-... # только в .env
ANTHROPIC_MODEL=claude-opus-4-5
```

Без ключа адаптер автоматически переходит в mock-режим (`is_mock == True`) и проект
продолжает работать полностью. Транспорт — `httpx`, поэтому SDK ставить не обязательно;
если хотите официальные SDK, есть `requirements-live-models.txt`.

Оба адаптера: структурированный JSON, валидация схемы, повторный запрос при невалидном
формате (`PARTICIPANT_MAX_RETRIES`, по умолчанию 2), таймаут
(`PARTICIPANT_TIMEOUT_SECONDS`, 60 с), сохранение имени модели, версии модели и версии промпта.
Ошибки API пишутся в таблицу `api_errors`, решение сохраняется со статусом `FAILED`
и отклоняется risk engine.

## Безопасность и секреты

- Ключи читаются **только** из переменных окружения; `.env` в `.gitignore`.
- `.env.example` содержит пустые значения — тест проверяет, что там нет реальных ключей.
- В БД и логи секреты не попадают: `services/audit.scrub()` рекурсивно маскирует поля,
  похожие на ключи; тест прогоняет весь SQLite-файл на наличие подставленных ключей.
- `GET /api/config` отдаёт конфигурацию с маской `***set***`.
- Нет приватных ключей, подписи транзакций и отправки ордеров — проверяется тестом,
  сканирующим репозиторий по списку запрещённых паттернов.

## Принятые допущения

1. **Snapshot фиксирует ровно одну точку во времени.** TTL по умолчанию 15 минут; любое
   решение по просроченному или заменённому снимку отклоняется.
2. **`stake_usdc` для `SELL`** трактуется как желаемая сумма выручки в USDC; фактический
   объём ограничивается размером открытой позиции.
3. **Одна позиция на пару (участник, рынок, исход)** — усреднение по цене входа.
4. **Расчёт рынка вводится оператором вручную.** Автоматического получения результата от
   Polymarket нет: результат матча важнее скорости, а ручной ввод исключает ошибки парсинга.
5. **Один активный раунд на рынок.** Новый раунд по тому же рынку создаётся после исполнения
   или отмены предыдущего.
6. **Деньги считаются во float с округлением** (суммы 2 знака, цены 4, размеры 6). Для
   бумажной симуляции этого достаточно и это детерминированно.
7. **Мок-участники имеют разные стили** (порог edge, доля Келли, смещение оценки), чтобы демо
   выглядело живым; при подключённых ключах mock не используется.
8. **Аутентификации нет.** Панель рассчитана на локальный запуск оператором. Если выкладывать
   её в интернет, нужен обратный прокси с авторизацией — особенно для страницы Титана.
